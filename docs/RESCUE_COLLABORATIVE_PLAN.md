# خطّة: مسار الإنقاذ التشاركيّ (Collaborative Rescue) — v2

> **الحالة:** مُراجَعة (v2) بعد ملاحظتَي المالك — **تصميم، لا كود بعد**. يُراجَع بنداً بنداً قبل أيّ `Edit`.
> **الجذر:** مسار الإنقاذ الحاليّ (`RESCUE_SEQUENCE`: خريطة المخاطر → أيزنهاور → RACI → جانت) **يفرض نموذجاً جامداً** ويتجاهل تشخيصه الخاصّ (المحاور الأربعة). المطلوب: **قيادة مرنة** — يفهم العميل وضعه، يُقترَح عليه الأضعف، ويضيف تحدّياته (حتى 3) — دون تشتّت.
>
> **تغييرا v2:** (١) كل شاشة مربوطة بخطوة `RESCUE_PLAN` صريحة (لا شاشات معلّقة). (٢) التحدّيات تُخزَّن في artifact **مملوك لنا** `RESCUE_CHALLENGES` — لا حقن في `RISK_REGISTER` (طائرة/ملك غيرنا)؛ جسر خريطة المخاطر مؤجّل.

---

## §1 — المبدأ الحاكم
**افهم ← اقترح الأضعف ← اسمح بالإضافة (حتى 3) ← نفّذ ← أعِد التدقيق.**
اقتراحٌ ذكيّ من التشخيص + تصحيحٌ يدويّ من العميل. لا فرض، ولا قائمة مفتوحة (سقف 3 يمنع الشلل). يُبنى **داخل النموذج الدلاليّ `RESCUE_PLAN`** (لا `RESCUE_SEQUENCE` القديم بالأدوات).

## §2 — التدفّق: كل شاشة = خطوة `RESCUE_PLAN` صريحة (إصلاح ١)
النموذج بعد الإضافة: **axis → challenges🆕 → action → initiative → reaudit** (إعادة ترقيم لـ5 خطوات).

| خطوة `RESCUE_PLAN` | الشاشة | الحالة | معيار القبول |
|---|---|---|---|
| *(قبل الإنقاذ)* | نتيجة التدقيق (34% خطر · 4 محاور) | ✅ موجودة | لا مساس |
| **`axis` (1)** | **افهم + اختر**: «أضعف محور = الفريق 22% · معناه…» + متنفّس «اختر محوراً آخر» | 🔧 تحسين عرض | يعرض الأضعف تلقائيّاً؛ يسمح باختيار محور مختلف يدويّاً |
| **`challenges` (2)** | **🆕 «أضف حتى 3 تحدّيات تعرفها»** | 🆕 خطوة | اختياريّ · ≤3 (الرابع مرفوض) · تخطّي بلا احتكاك |
| **`action` (3)** | **إجراء تصحيحيّ** — مُثرى بتحدّيات العميل جنب بنك المقترحات | 🔧 تحسين عرض | يعرض التحدّيات المُضافة مع مقترحات المحور |
| **`initiative` (4)** | مبادرة عاجلة | ✅ موجودة | لا مساس |
| **`reaudit` (5)** | أعِد التدقيق | ✅ موجودة | ≥40% → خروج من الأحمر |

> **حُذف من v1:** «S3 الخيار الموجّه» المنفصل (صار جزء `axis`) و«S4 خريطة المخاطر» كخطوة إلزاميّة (لم تكن في `RESCUE_PLAN` الدلاليّ أصلاً — كانت خلطاً مع `RESCUE_SEQUENCE`).

## §3 — الشاشة الجديدة (`challenges`)
- **السؤال:** «رصدنا [الفريق] كأضعف محور. تحبّ تضيف تحدّيات أخرى تعرفها قبل نبدأ؟»
- **إدخال:** نصّ حرّ، **حد أقصى 3** (الرابع مرفوض برسالة «ركّز على 3 في الأزمة»).
- **وسم اختياريّ:** لكل تحدٍّ ربطٌ اختياريّ بمحور (حوكمة/مالية/فريق/رقمي).
- **اختياريّة كاملة:** «تخطّي» → يكمل بالتشخيص وحده، صفر احتكاك.

## §4 — التخزين (إصلاح ٢ — ملكيّة نظيفة + حارس الفارغ)
- التحدّيات → **artifact جديد مملوك لنا `RESCUE_CHALLENGES`**:
  ```
  { items: { id: string; text: string; axis?: 'governance'|'financial'|'team'|'digital' }[] }
  ```
- **لا نمسّ `RISK_REGISTER` ولا `RiskMapPage`** (ضمن الطائرة 🔴 — ملك ok-computer). «من يملك الملف يملك إصلاحه».
- **يُقرأ بحارس `deepHasContent`** (درس ق٥): `{}` أو بلا items = لا تحدّيات، لا تعثّر.
- **الدمج (وجهة القرار أ):** يظهر في خطوة **`action`** — التحدّيات جنب مقترحات المحور، فتوجّه الإجراء التصحيحيّ. «أوقف النزيف» يشمل ما رصده العميل لا التدقيق وحده.
- **جسر خريطة المخاطر = قيد مؤجّل موثّق:** حين تخرج `RiskMapPage` من الطائرة، يُسطَّح `RESCUE_CHALLENGES` في `RISK_REGISTER` بوسم `origin:'client'` ودرجة **متوسّطة 3×3 قابلة للتعديل** (قرار §8-أ). **لا يُنفّذ الآن** — لا خرق ملكيّة.

## §5 — أين في الكود (ملفّاتنا فقط، لا محرّك جديد)
- **خطوة `challenges`** جديدة في `RESCUE_PLAN` ([rescue.ts:100](../client/src/journey/rescue.ts)) بين `axis`(1) و`action`(2) — إعادة ترقيم.
- **مكوّن شاشة** `RescueChallengesStep` (جديد) — يستهلكه سطح الإنقاذ خلف `USE_RESCUE_PLAN`.
- **نوع artifact جديد** `RESCUE_CHALLENGES` في `ArtifactType` (strategicApi) + قراءة/كتابة عبر `upsertArtifact` — ملفّاتنا.
- **تحسين عرض `axis` و`action`** (نصّ الفهم + عرض التحدّيات) — داخل مكوّنات الإنقاذ، لا خارجها.
- **صفر مساس:** `RiskMapPage` · `RISK_REGISTER` · `classify` · `useGuidedNext` · المسار الطبيعيّ.

## §6 — الحدود (ما لا يتغيّر)
- **المسار الطبيعيّ (≥40%) بلا مساس** إطلاقاً.
- **`RESCUE_SEQUENCE` القديم يبقى** للتراجع (flag off) — لا حذف.
- **السقف 3 صارم** · **اختياريّ** (تخطّي = بلا احتكاك).
- **`classify`/`useGuidedNext`/`RiskMapPage` لا تُمسّ** — الطبقة كلها داخل `RESCUE_PLAN` + artifact مملوك لنا.

## §7 — معايير القبول
1. عميل <40% يرى `axis` (افهم+اختر) ثم `challenges` (السؤال).
2. يقبل **حتى 3** — الرابع مرفوض برسالة واضحة.
3. **التخطّي** يكمل المسار بلا احتكاك.
4. التحدّيات المُضافة **تظهر في خطوة `action`** موجِّهةً الإجراء (لا في خريطة المخاطر — مؤجّل).
5. `RESCUE_CHALLENGES` يُقرأ بـ`deepHasContent`: فارغ `{}` → لا تحدّيات دون تعثّر.
6. المسار الطبيعيّ + `RESCUE_SEQUENCE` القديم + `RiskMapPage` بلا تغيير سلوكيّ.
7. اختبارات: السقف=3 · الاختياريّة · قراءة `RESCUE_CHALLENGES` الفارغ · إعادة ترقيم `RESCUE_PLAN` (5 خطوات، `challenges` بين axis وaction).

## §8 — قرارات مثبّتة
- ✅ **الوجهة:** التحدّيات تُوجّه خطوة `action` (قرار أ)؛ جسر خريطة المخاطر مؤجّل بلا خرق ملكيّة.
- ✅ **درجة الخطورة الأوّليّة (عند الجسر المؤجّل):** متوسّط **3×3 قابل للتعديل** — صفر احتكاك وقت الأزمة.
- ✅ السقف 3 · اختياريّ · وسم محور اختياريّ.
