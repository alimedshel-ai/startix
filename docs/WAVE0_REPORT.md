# تقرير الموجة صفر — تحقّق قبل البناء

> مخرَج الموجة صفر من خطّة الإصلاح (نسخة ٢). الهدف: حسم حجم العمل قبل كتابة المنطق. **لم تُلمَس أيّ واجهة.** كل بند له قرار من سطرين: يُستبدل بـ`useNext` · يبقى عرضاً · يؤجَّل.

---

## ٠) الخلاصة التنفيذيّة (اقرأ هذا أوّلاً)

الجرد أثبت فرضيّة الخطّة: **المشكلة تعدّد مصادر القرار — وعددها ٦**، لا كثرة الأسطح. لكنّه كشف أيضاً حقيقةً تُعدّل حجم العمل:

> **مصدر الحقيقة المقترح موجود بنسبة ~٧٠٪ سلفاً.** `journey.ts` (بيانات) ≈ `journeyStages.ts + rescue.ts + analysisPlan.ts`. و`useNext` (الحساب) ≈ `useGuidedNext.ts`. فالعمل الأساسيّ **ترحيل وتوحيد**، لا بناء من الصفر.

**توصية محوريّة (قرار للمستخدم):** لا نُنشئ ملفّين جديدين باسمَي `src/lib/journey.ts` و`src/hooks/useNext.ts` — فذلك يُنشئ **ازدواجاً** يناقض مبدأ الخطّة نفسه (مصدر واحد). بدلاً منه: نتبنّى `journey/*` + `useGuidedNext` **كالمصدر الأساسيّ** ونوسّعهما. (إن أردت الاسمين حرفيّاً، نعيد تسمية الموجودَين — لا ننشئ جديداً بجانبهما.)

## ٢) إجابات أسئلة الموجة صفر الصريحة

**أ) هل تشتقّ `RunCockpitPage` الخطوات أم تكتبها يدويّاً؟**
→ **تشتقّها** من `useJourney` (بيانات حقيقيّة: artifacts/SWOT/KPIs). القرار: **إصلاح ربط فقط** (توجيهها لـ`useGuidedNext`)، لا إعادة كتابة. ٣٠٢ سطراً، الخطر متوسّط (لأنها تكرّر الإنقاذ). تبقى وصيّة الخطّة: خلف flag `USE_JOURNEY_NEXT` مع تراجع.

**ب) جرد مواضع «التالي»** → الجدول أعلاه (٦ + تكرار إنقاذ القمرة).

**ج) فرع «لا صحة بعد»** → **موجود جزئيّاً**: `classify.ts` يُرجع `level:'assess'` («قِس أوّلاً»، journeyPath=null) بلا تدقيق؛ والإنقاذ لا يُقيَّم بلا قيمة صحّة (useRescue: حرج = تدقيق<٤٠، فبلا تدقيق لا إنقاذ ✓). والمشي على التسلسل يبدأ بالتدقيق تلقائيّاً. **الناقص:** جعله صريحاً بـ`reason:"no_health_baseline"` ورسالة موحّدة. عمل صغير.

**د) التشخيصات الثلاثة** (تدقيق ٤ محاور = صحّة · تحليل عميق ٦ محاور/٣ فئات = سياق · نضج بالتخصّص = نضج) → **تقيس أبعاداً مختلفة**. قراءة أوّليّة: تبقى مستقلّة؛ التدقيق يبقى منتِج الصحّة. **الجدول الكامل يُنقل إلى PR ١٠** (لم يكتمل ضمن سقف اليوم — كما تسمح الخطّة).

## ٣) تعارضات يجب حسمها أثناء الترحيل (لا تُلمَس الآن)

| التعارض | المكان | الحسم |
|---|---|---|
| **ترتيب ① مختلف** | ClientDetail: dept-deep→تدقيق→**PESTEL→7S**→SWOT (خارج قبل داخل، بلا العميق) | يُستبدل بترتيب المصدر: تدقيق→عميق→**7S**→…→**PESTEL**→②SWOT |

## ٥) معيار الخروج (تحقّق)

- ✅ قائمة مواضع واضحة (٦ مُقرِّرين + تكرار إنقاذ القمرة).
- ✅ قرار من سطرين لكل موضع (الجدول §١).
- ✅ سؤال القمرة محسوم (تشتقّ → إصلاح ربط).
- ⏭️ جدول التشخيصات الثلاثة → PR ١٠ (لم يكتمل ضمن اليوم، مسموح).
- 🟨 **قرار مُعلَّق للمستخدم**: تبنّي `journey/*`+`useGuidedNext` كمصدر (موصى به) أم إعادة تسميتهما لـ`journey.ts`/`useNext.ts` حرفيّاً؟

**لا يبدأ PR ١ قبل حسم هذا القرار الأخير.**
