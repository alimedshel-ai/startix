## ١. المصدر + تحذير النقل

`نظام_الإدارة_المالية_مُصحّح.xlsx` — ١٣ ورقة · ٥٦٧ صيغة · صفر أخطاء (بعد تصحيح ١٦٢ خطأً في الأصل).

**الأخطاء الـ١٦٢ المُصحّحة — يجب ألّا تتكرّر عند النقل:**

| الخطأ | الأثر | التصحيح |
|---|---|---|
| مرجع دائريّ `C4 = C3-C4` | ١٦٠ خليّة منهارة | الربح الإجماليّ = الإيرادات − التكاليف المباشرة |
| مراجع الإعدادات مزاحة صفوفاً | كل الأهداف تقارَن بأرقام خاطئة | إعادة تعيين كل مرجع لخليّته |
| مراجع دائريّة في الموازنة | العمودان F/G معطّلان | F = D×(1+E) · G = F ÷ الإجمالي |
| تواريخ غير موجودة (٣١ فبراير) | فشل صامت | آخر يوم لكل شهر |
| **عمود التاريخ نصّيّ** | كل المقارنات الشهريّة = صفر **بلا رسالة** | تواريخ حقيقيّة + `DATE()` |
| اتّجاه التقييم موحّد | مؤشّرات التكلفة «كلما زاد أفضل» | تقييم واعٍ بالاتّجاه |
| نسب السيولة على `AVERAGE` الحركات | أرقام بلا معنى | كتلة أرصدة مجمّعة |

> **قاعدة النقل الحاكمة:** الصيغ **لا تُنقل كصيغ** — تُعاد كتابتها **دوالّ صرفة + اختبارات** (نمط `classifyClient`/`getRescueNext`).
> خطأ إكسل تراه بعينك؛ الخطأ نفسه في كودٍ **يحسب بصمت ويُسلّم قراراً ماليّاً خاطئاً.**

## ٣. المُصنّف الماليّ — القاعدة المقترحة

### ⚠️ تصحيحان جوهريّان (من المستخدم — مُعتمَدان)

**(أ) لا تبنِ التصنيف على نِسب الربحيّة.**
نموذج البيانات لا يحوي ميزانيّة عموميّة؛ حقوق الملكيّة **رقم مشتقّ** (أصول − التزامات من تدفّقات الحركات).
فـ ROE ‏٩٢٪ وهامش إجماليّ ‏٩٧٪ **منتفخان بنيويّاً، لا دليل صحّة.** مصنّف مبنيّ عليها **يرفع كل عميل إلى «تميّز» زوراً.**

**(ب) جاهزيّة الاستثمار ليست مكافئ `classifyClient`.**
هي **بوّابة قرار** لاحقة (هل نتوسّع؟)، لا مقياس صحّة. الترتيب الصحيح: **صحّة ماليّة → مستوى → (ثمّ) جاهزيّة.**
خلطهما يجعل شركةً رابحةً شحيحةَ نقدٍ تُصنَّف «جاهزة» وهي في خطر سيولة.

### الترجيح المقترح (مرجّح نحو السيولة والتحصيل)

الإشارات الصادقة في البيانات الفعليّة: السيولة الفوريّة ‏٠٫١١ (هدف ١٫٠) · دوران العملاء ‏١٫٦٧ (هدف ١٢).

| المكوّن | الوزن | المبرّر |
|---|---|---|
| السيولة (فوريّة + سريعة) | **٣٥٪** | الإشارة الأصدق — لا تتأثّر بنموذج البيانات |
| التحصيل (دوران العملاء · نقدية/إيرادات) | **٢٥٪** | مصدر الخطر الفعليّ المكتشَف |
| كفاءة التكلفة (رواتب · مواد ÷ إيرادات) | ٢٠٪ | قابلة للقياس ومقارنة بأهداف |
| الربحيّة (هامش صافٍ فقط) | **١٠٪** | وزن منخفض عمداً — منتفخة بنيويّاً |
| الالتزام بالموازنة (فعليّ ÷ موازنة) | ١٠٪ | إشارة انضباط |

**العتبات:** موحّدة مع `classifyClient` — `<٤٠ طوارئ · ٤٠-٥٩ تأسيسي · ٦٠-٧٩ نموّ · ≥٨٠ تميّز`.
**تجاوز إجباريّ:** سيولة فوريّة `< 0.2` ⟵ **طوارئ** مهما كانت الدرجة (نظير `dangerZone === 'RED'`).

## ٤. الشخصيّتان

| | المدير المستقلّ (عميل) | المالي الداخليّ (شركة المالك) |
|---|---|---|
| المدخل | مؤشّرات مباشرة — قد لا يملك دفاتر العميل | النظام الكامل: حسابات + قيود + موازنة |
| القياس | لوحة المؤشّرات لكل عميل | + أداء الفروع + هيكل التكاليف |
| التصنيف | المصنّف الماليّ ⟵ المستوى | نفسه |
| التوجيه | نفس القمرة/المرساة — طوارئ ماليّ = سيولة حرجة | نفسه |
| التقارير | قالب بنكيّ / واتساب | حكوميّ / مجلس إدارة |

**الفرق الجوهريّ:** المستقلّ أخفّ — إدخال مؤشّرات مباشر دون شجرة حسابات كاملة.
يستلزم **مسارَي إدخال يلتقيان في شكل موحّد واحد** قبل الحساب (نفس دور طبقة التعيين).
