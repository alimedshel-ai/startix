## ٠) الخلاصة

| المحور | النتيجة |
|---|---|
| ملفات تالفة | **لا شيء** — كل الملفات تُصرَّف (tsc نظيف: عميل + خادم) |
| ملفات مكرّرة (محتوى متطابق) | **لا شيء** — md5 فريدة عبر ٢٤٩ ملفاً |
| ملفات يتيمة (غير مستوردة) | **لا شيء** — المُبلّغ عنها ملفات `*.test.ts` (تشغّلها vitest مباشرةً، ليست يتيمة) |
| ملفات ٥-أسطر | **wrappers مشروعة** (`HRAuditPage → <DeptAuditPage deptCode="HR"/>`) — نمط سليم لا تلف |
| tsc | **نظيف** (عميل ٢٤٩ ملفاً · خادم ٦٨ ملفاً) |
| البناء + الاختبارات | ✅ بناء ناجح · ١٣٩ اختبار |

**المخاوف (تلف/تكرار) لم تتحقّق.** ما كان يبدو «تكراراً» هو **ازدواج ترحيل مقصود ومتتبَّع** (توحيد الرحلة) — يُحذف في PR١٠، لا تلف عشوائيّ.

## ٣) الدَّين النظاميّ الوحيد — ٣٩ × `set-state-in-effect`

النمط: `useEffect` يستدعي `setState` متزامناً في جسمه (تحميل بيانات) → عبر ~٣٥ ملفاً (غالبها ١ لكل ملف؛ الأكثر: `CommandPalette` ٣، `StrategicPlanPage` ٣).

**الإصلاح المُثبَت** (استخدمناه سابقاً في `useRescue`): الاشتقاق أثناء الرندر عبر علامة `forId`/`loadedKey`، وsetState **بعد await** داخل callback فقط — لا متزامناً في الـeffect.

**التوصية**: حملة مخصّصة بدفعات صغيرة (٣-٥ ملفات/دفعة، تحقّق بعد كلٍّ) — لا إعادة كتابة عمياء لـ٣٥ ملفاً. الملفات (بالأولويّة):
`CommandPalette` ×٣ · `StrategicPlanPage` ×٣ · ثم مفردات: `useCompany` · `useClientScopedCompany` · `useJourneyCompletions` (هوكات — الأعلى أثراً) · بقيّة الصفحات.

## الحكم النهائيّ
المنصّة **نظيفة وصحيّة**. لا حاجة لـ«حملة إنقاذ». العمل المتبقّي = (أ) حملة الـ٣٩ set-state بدفعات، (ب) إكمال ترحيل توحيد الرحلة (PR٤–١٠)، (ج) تقسيم اختياريّ للملفات >١٠٠٠ سطر. كلها تحسينات مُدارة، لا إصلاح تلف.
