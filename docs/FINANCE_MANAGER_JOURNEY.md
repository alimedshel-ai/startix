# تصوّر تجربة العميل — مسار «المدير المالي المستقلّ»

> **مَن:** مستخدمٌ نوعه `MANAGER` · `managerType = INDEPENDENT_PRO` · `specialtyDeptType = FINANCE`.
> **المدى:** من التسجيل حتى التنفيذ والمتابعة (الحلقة الكاملة).
> **المصدر:** مبنيّة على الكود الفعليّ (مسارات، مراحل، دوالّ القرار). كل مشهد يشير إلى الملف/المسار الحقيقيّ — لا شاشات متخيَّلة.
> **ملاحظة على الدور:** المدير المالي المستقلّ **يُدقّق ويُخطّط لإدارات عملائه** (شركات أخرى)، لا لإدارته هو. فوحدة العمل = (عميل × إدارة المالية).

---

## خريطة سريعة (العقد والقرارات)

```
تشخيص ضيف (اختياري) → تسجيل → onboarding → /manager/clients (البيت الموحّد)
        │ سيولة/تتبّع                    │ توصية المسار (recommendPathFromFinancials)
        ▼                                ▼
   إشارات ماليّة ────────────────────► مسار مُقترَح (QUICK/MEDIUM/LONG)
                                         │
/manager/clients ──(NextActionHero)──► أضِف عميلاً → تدقيق المالية → المراحل ①→⑥
        ▲                                                    │
        └────────── الحلقة المتكيّفة: قِس→صنّف→وجّه→نفّذ→أعِد القياس ◄──┘
```

القرار المحوريّ يتكرّر في كل نقطة: **`classifyClient`** يشتقّ *المستوى* و*مسار الرحلة* من الصحّة، و**`useGuidedNext`/`getNextStep`** يترجمه إلى «خطوتك التالية».

## الفصل ٠ — قبل التسجيل: تشخيص الضيف (اختياريّ)

| البند | التفصيل |
|---|---|
| **المسار** | `/diagnostic/try` → [TryDiagnosticPage.tsx](../client/src/pages/TryDiagnosticPage.tsx) |
| **ما يراه** | تشخيصٌ قصير: **جوهر** (الهوية + المرحلة + الحجم + التتبّع الماليّ + السيولة) يُعطي نتيجةً فوريّة، ثم «أضِف دقّة (٤ أسئلة)» اختياريّة. |
| **المنطق** | الأسئلة الأربعة الاختياريّة تُملأ بقيمٍ حياديّة عند التخطّي فتبقى دورة الحفظ كاملة (لا تغيير في الخادم). |
| **الأثر على المسار** | إشارتا **السيولة + التتبّع الماليّ** تُخزَّنان في `diagnosticStore.ownerDraft` — وتُغذّيان توصية المسار في onboarding لاحقاً. |
| **النتيجة** | صفحة النتيجة الغنيّة (`/diagnostic/result`): المسار الموصى + النضج + الرادار + نقاط الضعف + إجراءات ٩٠ يوماً. |

> هذه مرحلة تسويقيّة «جرّب قبل أن تسجّل». إن دخل المدير مباشرةً بلا تشخيص ضيف، نبدأ من الفصل ١ بلا إشارات ماليّة (فلا توصية مسار مُسبقة — يختار يدويّاً).

| البند | التفصيل |
|---|---|
| **المسار** | `/manager/finance/audit` (`auditRouteFor('FINANCE')` في [journey/index.ts](../client/src/journey/index.ts) = `/manager/finance/audit`) |

| **⚠️ فجوة صادقة #٢** | تلقين التحليل العميق (`dept-deep`) مُخصّص لـ PROJECTS/SALES فقط؛ **المالية تسقط لتلقين GENERIC** — احتكاك أوّل مرّة (محتوى مؤجّل). |

## الفصل ٥ — القيادة المتكيّفة: التصنيف → المسار → الخطوة التالية

| البند | التفصيل |
|---|---|
| **التصنيف** | `classifyClient({hasAudit, healthPct, dangerZone, financialHealthPct?})` ([journey/classify.ts](../client/src/journey/classify.ts)) → `level` ∈ {assess, emergency, foundation, growth, excellence} + `journeyPath`. |
| **العتبات** | `<٤٠ طوارئ` (QUICK) · `٤٠–٥٩ تأسيسي` (QUICK) · `٦٠–٧٩ نموّ` (MEDIUM) · `≥٨٠ تميّز` (LONG) · RED يُجبر الطوارئ. |
| **قمرة القيادة** | `/manager/clients/:id/run` → [RunCockpitPage.tsx](../client/src/pages/manager/RunCockpitPage.tsx): لوحة العميل×الإدارة الواحدة (أين أنت + الخطوة القادمة). |
| **المُوجِّه** | `useGuidedNext` / `getNextStep` ([journey/nextStep.ts](../client/src/journey/nextStep.ts)) = مصدر «خطوتك التالية» الوحيد عبر كل الصفحات. |
| **فرع الطوارئ** | إن `level = emergency`: تسلسل الإنقاذ **risk → eisenhower → raci → gantt** يُعرَض كـ«التالي» (الطبقة الطارئة فوق المحرّك). |

**الحلقة المتكيّفة:** قِس (تدقيق) → صنّف (`classifyClient`) → وجّه (`useGuidedNext`) → نفّذ → أعِد القياس → صنّف من جديد. المستوى يرتقي تلقائيّاً مع تحسّن الصحّة.

## الفصل ٦ — المراحل المقفلة ①→④ (مفلترة بمسار المدير)

المراحل تُفلتر بـ `PATH_STAGES` ([journeyStages.ts](../client/src/lib/journeyStages.ts)) — فلا يُحبَس المدير خلف مرحلةٍ خارج مساره:

| المسار | المراحل الفعّالة |
|---|---|
| **QUICK** (سيولة حرجة/منخفضة) | ① ② ⑤ ⑥ — يقفز ③④ |
| **MEDIUM** (وضع متوسّط) | ① ② ③ ⑤ ⑥ |
| **LONG** (سيولة مرتفعة + تتبّع ناضج) | ① ② ③ ④ ⑤ ⑥ (كلها) |

| المرحلة | ما يفعله المدير المالي | الأدوات (نظير الإدارة مُفضَّل) |
|---|---|---|
| **① البيئة** (تشخيص) | يشخّص بيئة إدارة المالية | `internal-environment` · **`manager/dept-pestel`** · `manager/deep-analysis` · `value-chain` |
| **② التوليف** | SWOT ثم TOWS | `/swot` → `/tows` — **بوّابة ثنائيّة المصدر**: SWOT يحتاج داخليّاً (نضج/تدقيق) + خارجيّاً (PESTEL)؛ إن غاب الخارجيّ يُعاد التوجيه لـ PESTEL |
| **③ التوجّهات** (MEDIUM/LONG) | التوجّه + الفجوة + الخيارات | `/directions` · `/bmc` · **`manager/dept-gap`** · `/choices` · `/bcg` · `/ansoff` |
| **④ المؤشرات** (LONG) | أهداف + OKR + KPI + OGSM | `/measure` (Hub بتبويبات) |

> **مدير المالية نموذجيّاً MEDIUM أو LONG** (المالية تُحبّذ التتبّع)، إلّا إذا كانت سيولة العميل حرجة فيُدفَع إلى QUICK ليعالج النزيف أوّلاً قبل التخطيط البعيد — وهذا بالضبط ما تفرضه توصية المسار وفيتوات الصحّة الماليّة.

## الفجوات المكشوفة صراحةً (لا تُخفى)

1. **طبقة البيانات الماليّة المعاملاتيّة غير مبنيّة** → `computeFinancialHealth` معزول ومختبَر لكنّه لا يقود التصنيف بعد (لا KPIs حيّة). الأولويّة الأعلى لتفعيل الطبقة الماليّة كاملةً.
2. **تلقين التحليل العميق للمالية = GENERIC** → احتكاك أوّل مرّة في المرحلة ① (محتوى مؤجّل).
3. **المبادرات القديمة (ما قبل الإصلاح)** تبقى بلا مستوى/هدف حتى تُعاد أو تُضبَط إنلاين.
4. **صفحة نتيجة المدير أبسط من المالك** (لا رادار/سيناريوهات بعد) — تجميلٌ مؤجّل مطلوب.
